# PRD：飞行记录 — 进行中 / 已完成

**模块**：飞行记录  
**性质**：固化现网逻辑（As-Is）  
**日期**：2026-08-17

---

## 1. 一句话

**进行中** = 还在飞；**已完成** = 已落地且里程、时长够格，写入历史。统计只认已完成。

---

## 2. 判定依据

靠无人机 OSD 的 `mode_code`（与 DRC 无关）。

| 类型 | mode_code | 含义 |
|------|-----------|------|
| 飞行态 | 3–12、15–19 | 起飞、航线、返航、降落中、指令飞行等 |
| 非飞行态 | 0、1、2、13、14 | 待机、准备、升级、未连接 |

数据来源：飞机直连 OSD，或机场 OSD 的 `sub_device`（会话记在**无人机 SN**）。

**通用结案规则**（各模块共用）：

```text
进入飞行态 → 进行中（内存）
回到非飞行态 / 断报 >90s → 结案
里程 >0 且 时长 >5s 且 里程 ≤1000km → 已完成落盘
否则 → 无效，不落盘、不进统计
```

---

## 3. 按一级功能模块

### 3.1 概览统计（KPI）

| 指标 | 是否含进行中 | 是否含已完成 |
|------|--------------|--------------|
| 飞行次数 / 总里程 / 总时长 | 否 | 仅有效已完成 |
| 飞行中台数 `activeCount` | 是（当前会话数） | 否 |
| 在线设备数 | 与架次状态无关 | — |

### 3.2 飞行趋势

- 按日聚合次数 / 里程 / 时长  
- **只计有效已完成**，不含进行中、不含无效  

### 3.3 设备排行

- 按设备汇总架次、里程、时长  
- **只计有效已完成**  
- 进行中的飞机不计入排行次数，直到结案且有效  

### 3.4 飞行记录列表

| | 进行中 | 已完成 |
|--|--------|--------|
| 来源 | 内存会话 | 历史落盘 |
| 角标 | 「进行中」 | 「已完成」 |
| 降落时间 | `--` | 有 |
| 合并规则 | 与历史合并，按起飞时间倒序 | 同左 |
| 刷新 | 有进行中时约 30s 自动刷新 | 随查询 |

无效架次：正常不出现在列表；若有脏数据则标「无效」。

### 3.5 筛选与导出

- 设备类型 / 时间范围：同时作用于列表与统计（进行中一般不受历史时间窗限制，随实时会话带出）  
- 导出 Excel「状态」列：`进行中` / `已完成` / `无效`，与列表角标一致  

---

## 4. 里程 / 时长（简）

- 优先用 OSD **累计飞行距离 / 时间** 差值  
- 无累计字段时用墙钟  
- 单次增量 >1000km → 脏数据，重置基准  

---

## 5. 验收

- [ ] 起飞 → 列表出现「进行中」；KPI「飞行中」+1  
- [ ] 降落且有效 → 列表变「已完成」；KPI 次数/里程/时长增加  
- [ ] 太短 / 零里程 → 不落盘；趋势、排行不变  
- [ ] 断报 >90s → 按结案规则处理  

---

## 6. 对外口径

> 进行中是当前还在飞的架次；已完成是落地后满足「有里程、时长超过 5 秒」才记入历史的架次。概览、趋势、排行只统计已完成。
